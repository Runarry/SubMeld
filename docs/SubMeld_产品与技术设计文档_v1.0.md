# 01 项目命名与总体决策

## 1.1 名称与标识

项目名称定为 **SubMeld**，中文名为 **订融**。Sub 表示 subscription，Meld 表达把多种输入整理、合并成可用输出的产品意图。中文名强调订阅整理，不暗示代理内核、服务器托管或流量转发能力。

建议代码仓库名、命令名、容器服务名统一使用 `submeld`；内部包前缀使用 `@submeld/`；环境变量前缀使用 `SUBMELD_`。界面完整标识为“SubMeld · 订融”，文档简称“SubMeld”。这些是命名约定，不代表域名、商标、npm scope 或仓库名称已经注册或获得排他使用权。

## 1.2 一句话产品定义

SubMeld 是一个由用户自行部署、仅供授权用户使用的网页工具：接收节点链接、订阅内容和已支持的节点配置，解析为可编辑节点，生成 URI、Base64 订阅以及 Mihomo、sing-box、Xray 的节点配置和有限模板配置，并以可撤销的私人地址向客户端发布结果。

“转换”指同一个节点在不同表示格式之间转换，不是把服务端使用的协议改成另一个协议。把 VMess 文本改成 VLESS 字段不会使服务端支持 VLESS。表单生成的是客户端参数和分享链接，不负责开通服务器，也不保证随机生成的凭证已配置到服务端。

## 1.3 核心决策摘要

| 决策 | 首版选择 | 原因 |
| --- | --- | --- |
| 产品形态 | 一个网页应用、一个应用容器 | 控制部署与维护成本 |
| 转换上游 | 固定 Sub-Store 源码快照，受控构建 | 复用解析和输出能力，不运行其完整平台 |
| 技术栈 | Vue 3、TypeScript、Node.js 24 LTS、Hono、SQLite | 同一语言体系，单实例持久化 |
| 业务对象 | 来源、本地节点、订阅方案 | 不建立通用代理编排平台 |
| 输出语义 | URI、Base64、节点片段、完整模板分别命名 | 消除“Xray 等于 Base64”等歧义 |
| 默认转换策略 | 严格、可定位、不可静默丢失 | 宁可明确失败，不制造虚假成功 |
| 发布模式 | 先生成，再读取；按目标独立发布 | 客户端 GET 不触发抓取或转换 |
| 权限模式 | 单管理员与只读订阅令牌分离 | 自用但可部署到公网 |
| 配置验证 | 应用内静态检查；CI 中运行锁定内核 | 生产不安装和执行代理内核 |
| 许可证路线 | 项目自有代码按 AGPL-3.0 路线发布 | 与采用的上游授权相协调 |

Node.js 官方版本表在核对日期将 24 列为 LTS；Hono 提供 Node.js 适配；Vue 提供组件化界面能力；SQLite 的本地嵌入式、低写并发定位符合本项目假设。[S07][S09][S10][S11]

# 02 用户、使用场景与范围

## 2.1 用户与部署假设

首版只有一个管理员身份，可以在多台设备登录；没有公共注册、团队、组织、角色管理或租户。客户端持有某个订阅令牌，仅能读取该令牌允许的格式。外部订阅提供方不被视为可信代码来源，其响应内容始终按不可信输入处理。

部署假设为一台 Linux 主机、一个应用实例、本地持久卷和 HTTPS 反向代理。管理网页和 API 同源。外部网络只用于获取管理员明确配置的订阅来源；本地文本转换不需要访问任何外部服务。

## 2.2 三条主使用路径

**即时转换。** 登录后粘贴 URI、Base64 或支持的配置文本，直接预览节点和诊断；修改节点后复制 URI 或下载目标格式。此流程不要求先创建来源、订阅方案或数据库记录。

**手动生成。** 选择协议，填写地址、端口、认证、TLS 和传输字段；界面按目标能力提示不兼容项；由与导入节点相同的转换器生成输出。UUID 或密码可以辅助生成，但必须提示需要在服务端配置一致的值。REALITY 公钥等服务端相关参数不得用随机占位值冒充有效参数。

**私人订阅。** 保存远端或文本来源，组合本地节点，设置有限过滤和模板，生成私人订阅地址；手动或定时刷新来源；客户端读取最近满足有效性要求的产物。

## 2.3 v1.0 必须交付

首版包含即时转换、六类节点表单、节点导入与本地保存、来源管理、来源节点复制为本地节点、八种明确输出、有限配置模板、订阅发布、按设备创建及撤销令牌、来源刷新状态、结构化错误、单管理员认证、备份恢复和容器部署。

六类首发协议为 Shadowsocks、VMess、VLESS、Trojan、Hysteria2、TUIC。不同目标的承诺并不相同，具体见第 04 章。首版所有启用能力都必须通过对应测试，不能因为上游存在相关代码就标记为已支持。

## 2.4 明确不做

不做代理服务端安装、流量转发、服务器账户开通、内核运维、在线测速、IP 归属地查询、多跳链编排、任意路由迁移、远程规则执行、脚本插件市场、任意 JavaScript 处理器、云端同步、订阅收费、多用户权限系统和匿名公共转换服务。

不支持任意三内核完整配置的双向无损转换；不把 Base64 描述为加密；不把配置语法通过描述为网络连通验证；不通过自动关闭证书校验、切换协议或删除传输参数来“修好”节点。

## 2.5 后续扩展

v1.1 优先考虑 Xray/sing-box 原生 JSON 的限定节点提取、VLESS XHTTP、HTTPUpgrade、Shadowsocks 2022、AnyTLS 和 WireGuard。引入任一扩展前，必须补足输入字段、目标表达能力、客户端方言、诊断规则和测试样例，而不只是增加协议名称。

纯浏览器离线模式、外部身份认证和更多配置模板可以后续评估，不是首版完成的前提。扩展不得改变“生产环境不执行任意脚本或代理内核”的默认边界。

# 03 产品不变量与成功标准

## 3.1 十项不可破坏的不变量

| 编号 | 不变量 |
| --- | --- |
| INV-01 | URI 必须从解析后的节点重新生成；只有明确标注的“复制原文”可以返回原始字符串。 |
| INV-02 | Base64 解码结果必须逐字节等于同一批次的 URI 明文结果。 |
| INV-03 | 同一输入快照、目标配置和引擎版本产生确定输出；导出顺序不影响结果。 |
| INV-04 | 每个输入项有明确去向：输出、用户主动过滤、显式排除、阻断；不得无记录消失。 |
| INV-05 | 影响连接或安全语义的字段无法表达时，默认阻断该目标，不得静默弱化。 |
| INV-06 | 私人订阅 GET/HEAD 不抓取外部来源、不执行转换、不产生隐式写操作。 |
| INV-07 | 撤销令牌、禁用节点、删除来源或改变凭证后，旧产物不得绕过当前有效性检查。 |
| INV-08 | 新输入失败不会以空订阅或半成品覆盖成功产物；是否可继续读旧结果按明确失效策略判断。 |
| INV-09 | 节点凭证、原始订阅内容和完整私人地址不得出现在普通日志、遥测或浏览器持久缓存。 |
| INV-10 | 页面显示的“支持”“已校验”“已发布”分别对应明确能力、检查层级与产物状态。 |

## 3.2 完成标准

一个完整用户路径应能从粘贴真实格式的脱敏节点开始，完成编辑、重新生成 URI、生成 Base64、创建方案、取得客户端可拉取的私人地址、刷新来源、撤销地址，并在重新启动应用后保留正确状态。

验收报告必须包含预期节点数、实际节点数、关键字段断言、异常分支和所用引擎、模板、内核及客户端版本。截图、成功 HTTP 状态码和输出非空都不能单独证明转换正确。

# 04 格式、协议与配置能力契约

## 4.1 输入契约

| 输入类型 | v1.0 行为 | 边界 |
| --- | --- | --- |
| 单条或逐行 URI | 识别六类支持协议，逐项记录来源位置 | 空白与 BOM 规范化；不自动联网 |
| Base64 订阅 | 标准或 URL-safe 编码识别后，解析为 URI 列表 | 只允许一层订阅包装，不递归解码任意文本 |
| Mihomo/Clash YAML | 提取内联 `proxies` 节点 | 不导入整份规则、DNS 或代理组；不递归获取 provider |
| 节点对象列表 | 只接收文档声明的 JSON 节点输入结构 | 不把任意 JSON 误当成内核配置 |
| 远端订阅 URL | 仅从“远端来源”入口通过安全抓取模块获取 | 协议 URI 和订阅 URL 是不同输入通道 |
| Xray/sing-box 原生 JSON | 首版识别后返回“该输入路径尚未开放” | 不作为 Base64 或通用 JSON 继续猜测 |

HTTP/HTTPS 文本既可能是 URL，也可能是代理信息。首版通过入口选择解决歧义：在远端来源页它是待抓取地址；在本地解析页它只按所支持节点格式判断，绝不自动 fetch。解码后出现 URL 也不得触发二次抓取。

YAML 中的 `proxy-providers` 仅显示为未导入部分。存在内联节点时，可在明确确认“仅提取节点”后处理；只有 provider、没有内联节点时不得声称成功导入。提取节点不保留原配置的策略和路由语义。[S13]

## 4.2 八种输出标识

| 标识 | 内容 | 完整配置 |
| --- | --- | --- |
| `uri` | UTF-8 URI 列表，LF 分隔，默认无末尾换行 | 否 |
| `base64` | 对该批次 URI 字节做标准 Base64，保留 padding、不折行 | 否 |
| `mihomo-proxies` | 含 `proxies` 的 YAML 节点文档 | 否 |
| `singbox-outbounds` | 含 `outbounds` 的 JSON 节点文档 | 否 |
| `xray-outbounds` | 含 `outbounds` 的 Xray JSON 节点文档 | 否 |
| `mihomo` | 节点加版本化 Mihomo 模板 | 是 |
| `singbox` | 节点加版本化 sing-box 模板 | 是 |
| `xray` | 节点加版本化 Xray 模板 | 是 |

Base64 按 RFC 4648 的编码定义处理；输入兼容性和输出规范分开：可以读取允许的 URL-safe 变体，但默认只产生一种确定的标准 Base64 输出。Base64 不提供保密性。[S20]

Sub-Store 所查源码将 URI、V2Ray、Mihomo、sing-box 注册为不同输出器，其中 V2Ray 是 URI 列表编码；通用 JSON 是内部节点对象，不是 Xray 原生配置。本项目因此不把这些名称直接暴露为含糊的产品目标。[S02][S03]

## 4.3 首版协议验收矩阵

表中“纳入”表示本项目计划验证并开放，“不纳入”是本项目首版范围决定，不表示某个内核当前一定不支持该协议。所有“纳入”能力上线前状态仍为未验证。

| 协议 | URI / Base64 | Mihomo | sing-box | 自有 Xray 输出器 |
| --- | --- | --- | --- | --- |
| Shadowsocks | 纳入常用 AEAD 子集 | 纳入 | 纳入 | 纳入 |
| VMess | 纳入明确的分享格式 | 纳入 | 纳入 | 纳入 |
| VLESS | 纳入 TCP、WS、gRPC 限定组合 | 纳入 | 纳入 | 纳入 |
| Trojan | 纳入基础及已验传输组合 | 纳入 | 纳入 | 纳入 |
| Hysteria2 | 纳入已验 URI 方言 | 纳入 | 纳入 | 不纳入 |
| TUIC | 纳入已验 v5 URI 方言 | 纳入 | 纳入 | 不纳入 |

Shadowsocks 首版承诺 `aes-128-gcm`、`aes-256-gcm` 和 `chacha20-ietf-poly1305` 的已验路径；插件与 2022 系列不随基础支持自动开放。复杂端口跳跃、ECH、XHTTP 下载通道和未知实验参数不属于基础支持。

TLS、REALITY、flow、传输、认证算法及目标版本必须按组合判断。能力键建议包含 `protocol + transport + security + featureSet + targetProfile`，但实现采用有限的能力表和测试夹具，不引入通用规则引擎。

## 4.4 URI 方言与参数保真

同一协议可能存在多种分享格式或客户端约定。首版每个协议必须指定默认 URI 方言，并列出验收客户端和版本；尚未验证的方言只能显示为实验性，不能用于默认自动发布。

解析时保存已识别字段和未识别字段的位置。端口、SNI、ALPN、REALITY 公钥与 short ID、flow、传输 path、Host、serviceName、认证密码等不得因空字符串、数字推断或二次 URL 解码而改变含义。JSON 重复键和冲突的 URI 单值参数应拒绝，不用“最后一个覆盖”隐藏冲突。

URI 输入、表单编辑和配置输入统一进入结构化节点。URI 序列化后重新解析，只能作为一致性测试之一；最终仍需与独立预期字段和实际客户端行为对照，避免同一个解析器与输出器共同犯错。

# 05 总体架构与工程组织

## 5.1 部署与模块结构

```text
浏览器 / 订阅客户端
          |
      HTTPS 反向代理
          |
  SubMeld 单实例应用
    |-- 管理 API 与静态网页
    |-- SourceFetcher：唯一来源抓取入口
    |-- ApplicationService：节点和订阅用例
    |-- ConversionWorker：受限并发转换
    |-- Publisher：生成、检查、原子发布
    |-- Repository：SQLite 事务与加密存储
          |
     本地数据卷 + 独立密钥文件
```

这些是代码职责，不是微服务。前端只访问本应用，不调用第三方转换站点，不从 CDN 动态加载转换核心。生产镜像不包含 Xray、sing-box 或 Mihomo 可执行程序，也不挂载 Docker socket。

## 5.2 技术栈与版本原则

前端使用 Vue 3、TypeScript 和 Vite；后端使用 Node.js 24 LTS、TypeScript、Hono；持久化使用 SQLite 3，驱动选择 better-sqlite3 并固定版本；只执行有界的短同步查询和事务，不开放动态扩展加载。驱动的原生构建在 linux/amd64 与 linux/arm64 分别验收，不能从 Node 版本兼容声明推断镜像已经可用。[S23]接口校验采用共享 schema，前后端类型由同一契约生成或导出。[S07][S09][S10][S11]

精确运行时补丁、构建工具、SQLite 驱动、转换上游、测试内核与容器摘要在 M0/M1 写入锁文件。本文不虚构尚未构建验证的依赖版本组合。发布检查必须拒绝未填写版本、浮动 `latest` 和未固定摘要的生产镜像。

SQLite 数据库只放本地文件系统；启用外键、WAL、忙等待和短写事务。网络抓取、解析与配置生成都在数据库事务外完成。单实例是明确约束，不用共享 SQLite 文件模拟多副本服务。[S11][S12]

## 5.3 建议目录

```text
submeld/
  apps/
    web/                    # Vue 网页
    server/                 # API、抓取、存储、发布、CLI
  packages/
    contracts/              # API、节点编辑 DTO、诊断类型
    converter/              # 上游桥接、严格驱动、Xray 输出
  vendor/sub-store/         # 固定上游源码及许可证
  patches/sub-store/        # 可回放的少量补丁
  templates/                # 随版本发布的目标模板
  fixtures/                 # 完全脱敏的协议与失败样例
  tests/                    # 单元、集成、客户端与安全测试
  deploy/                   # 镜像、Compose 示例与运行说明
  docs/                     # 设计、能力表、升级和恢复手册
  upstream.lock.json
  compatibility.lock.json
  pnpm-lock.yaml
```

不为每个业务对象建独立包，不引入服务总线、插件容器、通用任务 DSL 或泛化数据库抽象层。模块间通过明确函数和有限 DTO 协作。

## 5.4 Worker 边界

默认启动一个转换 Worker，一次处理一个转换批次；主线程负责 I/O 和短数据库事务。队列容量、累计输入大小和等待时间都有上限，超限立即返回可解释错误。超时必须终止对应 Worker 并重建，不能只用 Promise 超时后继续让计算占用资源。

Worker 用于避免解析阻塞主事件循环，但不是恶意代码安全沙箱；Node 文档中的资源限制也不能视为整个进程所有内存的硬上限。生产仍需要容器内存限制、受控依赖和不开放脚本执行能力。[S08]

转换 Worker 不接收密钥、数据库连接、订阅抓取权限或任意文件路径，只接收有大小限制的文本、结构化节点和内置目标配置。原始请求结束后及时释放引用，空闲时可回收 Worker；不承诺 JavaScript 堆中的秘密可被即时物理清零。

# 06 Sub-Store 集成与上游维护

## 6.1 已知依据与未知边界

设计参考固定快照 `ece585cdac30d6a6f25a2b8815ac1dde26414153`。其官方 `proxy-utils.esm.js` 入口导出 `parse` 与 `produce`；这为独立转换提供入口，但不能据此推断它已经是无副作用、严格诊断的纯 SDK。[S01]

所查核心依赖运行时应用对象；相关初始化含环境、缓存和全局对象处理；`produce` 存在对节点对象的修改、过滤和输出错误回退。因此必须受控集成，而不是把压缩 ESM 文件直接导入主服务并沿用所有默认行为。[S04][S05]

此快照是可复核的设计参考，不宣称它是上线时最新版本。最终采用的上游提交需要通过 M0 实验确定，再写入锁文件。

## 6.2 受控构建方案

优先沿用官方入口定位必要逻辑，创建项目自有的薄转换入口。通过构建期适配替换上游应用运行时，提供请求局部的脱敏诊断接收器；只保留解析、必要规范化和选定输出器。

不得为了避免副作用在主线程临时篡改 `process`、`console` 或全局环境变量。不得简单绕过上游核心驱动而遗漏其必要规范化。确需提取或修改相关函数时，必须记录原文件、变更原因和对应回归测试。

构建检查记录依赖图；运行检查验证导入与转换不会创建缓存文件、联网、启动定时器、修改全局原型或执行脚本。仅“不导出脚本 API”或“打包时摇树优化”不能替代这些验证。

## 6.3 诊断钩子与兼容层

解析入口需要返回输入项定位、输出节点、未知字段和失败原因。若上游只记录日志，应在最小必要位置增加结构化钩子；日志只用于辅助定位，不以匹配英文日志文本作为长期接口契约。

上游的 `supported` 标记和项目自己的能力表分开。项目能力表决定允许的目标与参数组合，上游标记只能作为补充。解析成功不代表某个输出器可以完整表达节点；输出非空也不代表字段全部保留。

## 6.4 升级与退出条件

上游升级只能通过维护分支进行：更新提交与依赖锁，重放补丁，比较解析结果和目标输出，运行安全副作用测试与内核测试，人工审阅语义差异，再更新生产版本。运行时不自动下载上游代码。

建议触发额外架构评审的阈值为：补丁改动超过 8 个上游业务文件、持续手工维护超过约 500 行业务逻辑，或每次小版本升级都需要修复相同耦合。阈值是维护预算，不是质量证明。若核心无法做到可观察、可隔离和可稳定升级，应停止继续扩张产品界面，先解决集成路线。

# 07 转换流水线与错误模型

## 7.1 八步流水线

**输入守卫。** 检查字节数、编码、结构深度和格式声明；处理 BOM、换行；拒绝 HTML 错误页、冲突格式和超限输入。Base64 严格检查字符集和解码结果，不把任意乱码当节点。

**格式分派。** URI 按行分派，YAML/JSON 按结构分派；管理员可显式选择格式覆盖自动识别，但不能绕过格式校验。不得把解析失败的 JSON 再作为 Base64 无限尝试。

**解析与定位。** 为每项生成输入引用；记录行号或 JSON/YAML 路径；调用上游及限定适配器，保留未知字段的存在性和位置。

**结构化校验。** 检查地址、端口、认证、TLS、REALITY 与传输组合；规范化已定义的别名，不修改密码、私钥或 path 的实际字节语义。

**用户变换。** 只允许启用状态、协议过滤、名称包含/排除、固定前后缀、排序和可选精确去重。首版不用任意正则和脚本；每个排除项可追溯。

**目标预检。** 对协议、传输、安全和特性组合进行能力判断；必要字段缺失、未知关键字段或目标无法表达时阻断。

**独立输出。** 每个目标使用独立深拷贝；URI 只生成一次，Base64 从同一 URI 文本生成；Xray 原生输出使用自有小型适配器。

**结果检查。** 检查输入输出数量、唯一标签、默认引用、格式可解析性和预期关键字段；输出内容与诊断同时返回，但仅无阻断错误的产物可以进入发布流程。

## 7.2 转换返回结构

以下是项目接口设计，不是上游已经提供的函数签名。

```typescript
type Diagnostic = {
  code: string;
  severity: 'info' | 'warning' | 'error';
  stage: 'input' | 'parse' | 'validate' | 'produce' | 'publish';
  inputRef?: string;
  nodeId?: string;
  target?: string;
  fieldPath?: string;
  message: string;        // 不含原始凭证或完整 URI
  blocksExport: boolean;
};

type ConversionResult = {
  status: 'ok' | 'partial' | 'failed';
  counts: {
    inputItems: number;
    parsedNodes: number;
    userFiltered: number;
    explicitlyExcluded: number;
    outputNodes: number;
    rejectedItems: number;
  };
  diagnostics: Diagnostic[];
  outputs: Record<string, TargetOutput>;
  engineRevision: string;
};
```

URI 中的一行通常对应一个输入项；结构化配置中的一个节点对象对应一个输入项。无关配置段单独记录为“未导入配置范围”，不混入节点数量。每个目标独立统计，不要求所有目标节点数相同，但差异必须由用户过滤或显式错误解释。

## 7.3 错误分级与导出策略

| 代码示例 | 含义 | 默认行为 |
| --- | --- | --- |
| `INPUT_FORMAT_AMBIGUOUS` | 格式无法可靠判断 | 要求选择格式，不联网猜测 |
| `INPUT_LIMIT_EXCEEDED` | 大小、深度或节点数超限 | 拒绝该批次 |
| `NODE_REQUIRED_FIELD_MISSING` | 缺少连接必需字段 | 阻断相关节点/目标 |
| `TARGET_FEATURE_UNSUPPORTED` | 目标无法表达已知特性 | 阻断该目标 |
| `UNKNOWN_FIELD_UNACCOUNTED` | 存在未解释且可能影响连接的字段 | 阻断默认导出 |
| `NODE_FILTERED_BY_USER` | 管理员的过滤规则排除节点 | 信息提示并记数 |
| `EXPORT_NODE_MISSING` | 上游未输出某节点且原因不充分 | 阻断，不猜测精确原因 |
| `WORKER_TIMEOUT` | 转换超出执行预算 | 终止 Worker，无产物发布 |
| `PUBLICATION_SUPERSEDED` | 生成期间依赖已经变化 | 丢弃该结果并合并触发新生成 |

即时转换允许管理员显式排除失败节点后重新生成。自动发布只使用已经保存的过滤条件；不能在刷新失败时临时新增“忽略不支持项”。首版不提供对整个方案永久开启的“忽略所有错误”开关。安全风险确认单独保存在方案的 riskApprovals 中，绑定节点连接身份、风险类型和目标，不作为忽略未知字段或解析错误的通用豁免。

## 7.4 确定性与去重

不使用随机端口或当前时间作为导出默认值。必须补齐的值在节点规范化阶段确定并保存；无法合理确定则报错。标签以稳定节点标识派生，冲突按稳定顺序确定扩展长度，不依赖数组偶然顺序。

默认不去重。开启精确去重时，只对连接相关字段和受支持扩展完全相同的节点合并；名称不是唯一依据。保留第一个明确排序项的显示名称并记录被合并项。不因同地址、同端口而合并凭证、TLS 或传输不同的节点。

# 08 节点模型与编辑契约

## 8.1 模型边界

内部节点使用项目包装的 `NodeEnvelope`：项目 ID、来源引用、模型版本、引擎版本、结构化 payload 和诊断摘要。适配器内部可沿用上游字段表达，但数据库其他模块和前端不得随处操作上游私有字段。

前端编辑使用项目稳定的 `NodeDraft`：协议、名称、服务端地址、端口、认证、TLS、传输及协议特有字段。DTO 到上游 payload 的映射集中在 converter 中。保存时由服务端重新校验，不能信任前端已经显示“有效”。

模型只描述单个节点，不纳入任意路由图、策略图或 DNS 编排。未知字段可以保留在隔离的原始输入记录中，但不得无校验地透传到其他目标。

## 8.2 来源节点与本地节点

来源节点只读，归属于特定来源内容版本。要修改连接参数，使用“复制为本地节点”；复制后与来源更新脱离，只保留来源备注用于人工追溯。来源刷新绝不覆盖本地节点。

来源节点的稳定指纹基于已规范化的连接字段，不包含显示名称、数组位置或刷新时间；使用安装级稳定 identityKey 计算 HMAC，避免公开可枚举的凭证指纹。identityKey 独立随机生成并由主密钥加密保存；主密钥轮换只重新包装它，不改变节点身份。指纹只用于身份匹配，不表示跨安装通用 ID。

如果来源节点的认证、地址或重要连接参数改变，应视为新的连接身份。绑定到旧身份的默认节点失效时必须提示重新选择，而不是偷偷选择第一项。

## 8.3 表单设计

基本区显示名称、地址、端口和协议认证；TLS 区显示启用状态、SNI、证书校验、ALPN 和必要 REALITY 参数；传输区按协议与目标开放字段；高级区只展示已经受支持的附加选项。

编辑名称不能改变连接语义；编辑 TLS 或传输时立即展示受影响目标。密码默认遮罩，按需短暂显示；保存已有秘密采用“保留、替换、清除”三态，空输入不被默认为清空秘密。

默认开启证书验证。导入明确要求跳过验证的节点时保留其风险信息，不擅自改值；默认严格发布要求管理员针对该节点确认风险。来源凭证或关键安全参数变化后，之前的风险确认不得自动适用到新的连接身份。

# 09 来源获取与刷新机制

## 9.1 Source 结构与版本

来源类型只有 `remote` 和 `text`。远端来源保存加密 URL、受限请求头、刷新间隔和格式声明；文本来源保存加密原文。共同保存来源名称、启用状态、配置修订、内容修订、最近成功时间、最近尝试时间、状态和诊断摘要。

`configRevision` 在管理员修改地址、请求凭证、格式或启用状态时递增；`contentRevision` 仅在接受的内容或其规范化节点集合发生实际变化时递增。304 或相同内容的有效刷新只更新时间，不制造无意义的新内容版本。

每个来源最多保留当前接受快照与一个待检查候选，不建立无限历史。最近失败响应不保存完整 HTML 或错误页，仅保留有限、脱敏的状态摘要。

## 9.2 刷新调度

默认每 6 小时刷新一次，最小自动间隔 15 分钟，加入少量抖动。一个来源同一时间只有一个刷新；重复点击合并为同一操作。远端请求并发默认 2，转换并发默认 1。

调度器在应用进程内运行，记录 `nextRefreshAt`，重启后只合并补做一次到期刷新，不重放所有错过的周期。没有独立调度服务或永久任务队列。正在执行的操作在重启后标记为 interrupted，后续根据当前来源状态重新计算。

来源抓取和发布生成采用不同操作：刷新得到新的接受快照后，标记相关订阅目标待生成；不让客户端请求参与刷新工作。

## 9.3 安全抓取契约

所有网络访问必须走 `SourceFetcher`。默认只允许 HTTPS 和 443 端口；额外 HTTPS 端口由部署级 allowlist 显式配置。首版不开放关闭证书校验的抓取开关，也不读取系统代理环境变量作为隐式出口。

新增来源时登记规范化主机名和端口作为该来源允许的 authority。每次请求都校验 URL、DNS 的全部 A/AAAA 结果及实际连接地址；拒绝回环、私网、链路本地、元数据服务、组播、未指定及保留地址，处理 IPv4-mapped IPv6 和非常规 IP 文本。连接必须绑定到已校验地址，同时保留正确的 TLS SNI、证书主机名校验和 Host，避免校验后重新解析产生竞态。

默认不跟随重定向。管理员显式允许时最多 2 跳，每跳重复全部校验；只允许已授权 authority，跨 authority 不转发认证头。拒绝 URL userinfo、反斜线、控制字符、CRLF 和有歧义的主机表达；路径及查询按统一解析器处理，不进行不必要的重新编码。SSRF 防护还应配合主机或容器出口策略。[S14]

来源抓取的地址限制不等于节点 server 字段的限制：私网节点可以保存或导出，因为本应用不会主动连接该节点。不得为了支持私网节点而放宽 SourceFetcher 的公网出口边界。

请求头仅允许配置 User-Agent、Accept 和专门的 Authorization 秘密；禁止任意 Host、Cookie、转发头及换行。预先检查 Content-Length，但始终按实际接收字节限制；对解压后的内容另设上限。响应读取失败、超限或取消后必须关闭连接。

## 9.4 来源状态与接受规则

| 状态 | 触发 | 是否允许旧产物继续被读取 |
| --- | --- | --- |
| ready | 最近内容可接受 | 允许，仍检查有效期与依赖版本 |
| refreshing | 正在尝试刷新 | 允许读取此前有效产物 |
| degraded | 超时、临时 DNS/网络失败、429 或 5xx | 仅在原依赖未变且陈旧期限内允许 |
| needs-review | 200 空结果、HTML、解析异常或不完整输入 | 默认阻断，不把旧内容当新成功 |
| blocked | TLS/SSRF 校验失败、401/403/404、已知过期 | 阻断，要求管理员处理 |
| disabled | 管理员停用来源 | 立即使依赖它的产物失效 |

HTTP 200 不等于有效订阅。得到格式正确但零节点的内容时，不返回空成功订阅，也不长期保留可能已撤销的旧节点；来源进入 needs-review，并阻断相关发布。管理员可修复、替换或从方案中移除来源后重新生成。

临时失败采用有上限退避；首次尝试之后最多自动重试 2 次，尊重合理范围的 Retry-After。认证失败、证书失败、SSRF 拒绝和格式错误不自动高频重试。

# 10 订阅方案、模板与发布

## 10.1 订阅方案结构

一个订阅方案保存名称、启用状态、有序来源引用、有序本地节点引用、有限筛选与改名配置、各目标设置和方案修订号。令牌、产物和最近执行状态是关联技术记录，不嵌入节点 payload。

筛选顺序固定为：选择输入、协议过滤、名称包含/排除、显式排除、改名、可选精确去重、稳定排序。操作次序在界面中可见。各目标可以保存不同的协议过滤条件，例如管理员明确为 Xray 排除首版未开放的协议；系统不得代替管理员自动新增过滤。

## 10.2 三类完整配置模板

首版每个目标提供一个 `basic-proxy` 模板，支持有限参数，不允许上传或执行任意模板代码。模板随应用版本发布，不在运行时抓取远程模板。

共同约束：监听回环地址，默认本地端口 1080；不启用 TUN、不监听公共网络、不打开远程控制 API、不引用远程 provider 或外部脚本；用户代理流量的最终默认出口为指定代理，不配置代理失败后自动直连。

Mihomo 与 sing-box 模板可以包含手动选择组，并使用明确的默认节点绑定；Xray 模板包含可用 outbounds，通过路由指向明确选定的 active outbound，不把它描述成具有等价交互式选择组。Xray 默认节点更改通过管理端重新生成配置。

默认节点引用可以是本地节点 ID，或来源 ID 加连接指纹。来源刷新后该引用消失，完整配置目标进入 blocked，要求重新选择；URI 和节点片段目标不因缺少默认引用而被不必要阻断。

DNS 首版采用明确标注的系统解析/基础解析预设，不宣称“所有 DNS 均通过代理”或“绝无 DNS 泄漏”。代理服务器域名的引导解析与应用域名解析分开记录；需要更强 DNS 隐私或复杂分流时属于后续专用模板。三个内核的完整配置结构和出站语义需要分别适配，不进行字段名机械替换。[S13][S18][S19]

## 10.3 模板安全与版本

模板 manifest 至少包含 ID、版本、目标、测试内核版本、可编辑参数 schema、默认节点要求和检查命令类型。只允许修改声明过的参数；禁止通过任意深度 merge 注入文件路径、监听地址、脚本或远端资源。

完整配置以“节点输出 + 目标专用组装器 + 模板参数”生成；数组和引用由组装器构造，不使用字符串替换拼 JSON/YAML。模板升级改变语义时，必须提高模板版本并重新生成产物。

## 10.4 发布依赖向量

每个目标产物至少绑定：方案修订、所有参与来源的配置与内容修订、本地节点修订、引擎修订、模板版本、目标设置哈希和产物创建时间。订阅 GET 检查当前引用、来源状态、禁用状态和允许陈旧期限。

抓取、解析和生成在事务外完成；提交产物时以比较并交换的方式核对依赖向量。生成期间任何输入变化，都丢弃旧结果，不允许“后完成的旧任务”覆盖新配置。

首次发布必须至少有一个有效节点。空方案、所有节点被过滤或所选节点全部无法转换时，返回明确错误，不发布空列表或只有 DIRECT 的完整配置。

## 10.5 产物状态与旧结果规则

| 事件 | 当前目标状态 | 旧产物策略 |
| --- | --- | --- |
| 首次创建，尚未生成 | pending | 无旧产物，返回 503 |
| 生成和检查成功 | ready | 原子替换当前目标内容 |
| 同内容来源发生临时网络错误 | stale | 依赖未变、来源允许降级且期限内可读 |
| 接受了新的来源内容版本 | pending / ready | 旧依赖向量失效；生成完成前返回 503 |
| 新快照在某目标无法表达 | blocked | 该目标不得读旧版本；其他成功目标独立可用 |
| 来源返回异常空内容或解析异常 | blocked | 默认停止旧内容分发，等待管理员处理 |
| 管理员删除/禁用/修改凭证 | invalidated | 事务内失效，禁止旧内容继续分发 |
| 令牌撤销或方案停用 | unavailable | 后续请求拒绝，不依赖产物缓存是否存在 |

只有临时抓取失败允许陈旧读取；其期限默认是距离相关远端来源最近有效成功时间不超过 24 小时。多来源方案取最早到期者。有效 304 可以刷新成功时间；仅重新生成旧内容不能延长来源有效期。本地节点方案没有远端刷新到期，但仍受修订与权限检查。

源站明确返回认证失效、资源不存在、证书失败或已知到期信息时，不能使用“短暂网络失败”规则继续分发。已发给客户端的配置无法被服务器强制收回；撤销只约束后续请求，泄露节点凭证需要同时在服务端轮换。

## 10.6 对外 HTTP 契约

路径统一为 `/s/<token>/<format>`，format 为第 04 章定义的八个标识。有效令牌只读，且限制到单个方案与允许的格式集合。禁用或不存在的格式不自动回退到其他格式。

成功响应的 Content-Type 与格式一致；URI/Base64 使用 `text/plain; charset=utf-8`，JSON 使用 `application/json`，YAML 使用经客户端测试确认的 YAML 类型。文件名由服务端生成固定安全名称，不能直接使用未经处理的来源名称。

默认 `Cache-Control: private, no-store`，反向代理和 CDN 必须绕过缓存；不使用 Service Worker 缓存订阅内容。首版不提供订阅响应的 304 优化，避免权限失效与共享缓存交互复杂化。HEAD 与 GET 执行相同权限和有效性检查，但不返回正文。

无效、过期、撤销令牌及越权格式统一返回 404；有效令牌对应产物尚未可用时返回 503 和有限 Retry-After；方法不允许返回 405；均不跳转登录页、不返回前端 HTML 或包含上游 URL 的错误。允许陈旧读取时返回明确的 `X-SubMeld-Stale: 1`，详细原因只在管理页显示。

源站流量元数据仅在语义清楚时提供：单来源且保留其含义时可以展示经过校验的原始配额信息；多来源合并默认不输出伪造的总流量、总配额或到期时间。界面标注这些信息来自上游，并非本工具实际计费统计。

| `sessions` | token_hash、admin_id、csrf_ciphertext、expires_at、last_seen_at | 会话令牌不存明文；可整体吊销 |

| `subscription_inputs` | subscription_id、source_id 或 local_node_id、position | 两种引用恰好一个非空；使用实际外键 |
| `published_artifacts` | subscription_id、target、依赖向量、加密正文、状态、生成版本 | 每个方案/目标一条当前产物 |

模板以受版本控制的文件保存，不增加在线模板管理表。来源节点集合以加密快照保存，不为每次解析生成永久节点行；本地节点才拥有独立可编辑记录。

## 11.2 事务与并发

管理员写入使用 `expectedRevision` 乐观并发控制；不匹配时返回 409，并要求重新加载或人工比较，不做无提示的最后写入覆盖。单管理员多设备也可能出现并发编辑。

删除或禁用引用对象时，同一事务标记相关产物失效。发布成功时，同一事务核对依赖向量并更新正文、元数据和状态。失败产物和成功产物不能出现正文、节点数、版本号分别属于不同批次的混合状态。

来源刷新按来源 ID 串行，方案生成按方案 ID 合并；新修订优先，旧任务结果禁止提交。订阅读取使用一次受控读取流程核对令牌与有效性。权限撤销影响事务提交后开始的新请求，不能撤回已经在网络中传输的字节。

## 11.3 加密与秘密分类

完整来源 URL、Authorization、原始内容、节点 payload、会话 CSRF 秘密和产物正文按字段使用认证加密保存。采用成熟密码库提供的 AES-256-GCM，随机 nonce，AAD 绑定表名、记录 ID、字段与格式版本；主密钥为独立生成的 32 字节随机值，由只读秘密文件注入。不同用途的密钥使用标准 KDF 分离，不自行设计加密算法。[S17]

密码只保存专用密码哈希；高熵会话和订阅令牌保存摘要，不用可逆加密代替权限凭证设计。主密钥不放数据库、镜像、仓库或普通环境值；缺少或不匹配时启动失败，不生成新密钥“继续运行”。

字段加密保护数据库副本中的敏感正文，但不防主机 root、运行中进程或拿到主密钥的攻击者。名称、状态、计数、时间等元数据仍可能明文存在，备份仍须作为敏感文件管理。数据库、WAL、临时文件和错误日志都要纳入泄露测试。

## 11.4 备份与恢复

提供本地 CLI 备份和恢复，不提供任意上传数据库覆盖生产的网页入口。备份通过 SQLite 在线备份机制或停机一致性快照完成，不能在应用写入时只复制主数据库文件忽略 WAL。[S12][S21]

备份包含数据库、schema 版本、应用版本、转换与模板锁信息、校验摘要；主密钥单独安全保管，不自动打进同一份备份。保留建议为最近 7 份，由部署者安排执行，备份目录不作为静态资源提供。

恢复先在临时目录验证文件格式、完整性、schema 兼容和秘密解密，再停写并原子切换。默认吊销管理员会话；订阅令牌默认也吊销，恢复操作者可通过本地显式选项保留原令牌，但必须理解这会保留历史授权。令牌只存摘要，备份也不能帮助重新显示其明文。

主密钥轮换采用维护窗口下的离线重加密、完整验证和原子切换；旧备份的配套旧密钥不得在未更新备份前删除。首版不建立远程 KMS 或复杂在线多密钥编排。

# 12 API 设计

## 12.1 统一规则

管理 API 前缀为 `/api/v1`；除登录、有限健康检查外均要求管理员会话。写请求为 JSON，要求同源、CSRF token 和服务端 schema 校验；日志只记录路由模板与对象 ID，不记录原始请求正文。

ID 为不透明标识；分页采用固定顺序的游标；默认页长 50，最大 200。拒绝未知写入字段，限制字符串长度和数组项数。秘密字段的读取、替换、清空使用明确接口语义，列表接口默认不返回原文。

普通成功响应含 `data` 和 `requestId`；错误响应含稳定 `code`、脱敏 `message`、可选诊断和 `requestId`。HTTP 400 表示请求结构错误，401 未认证，403 同源/CSRF 拒绝，409 修订冲突，413 超限，422 无法满足转换或业务约束，429 限流，503 暂时不可用。转换预览可以返回 HTTP 200 加 `status: partial`，但导出被阻断时不能返回伪成功文件。

## 12.2 认证与转换接口

| 方法与路径 | 作用 | 关键约束 |
| --- | --- | --- |
| `POST /auth/login` | 登录并创建会话 | 同源与限流；失败信息统一 |
| `GET /auth/me` | 当前身份及 CSRF 信息 | no-store；不返回密码摘要 |
| `POST /auth/logout` | 吊销当前会话 | 写操作保护 |
| `POST /auth/reauth` | 敏感操作短时再认证 | 默认有效 5 分钟 |
| `POST /convert/parse` | 本地文本/节点输入解析 | 无网络；返回节点及定位诊断 |
| `POST /convert/produce` | 从编辑后的节点生成目标 | 必须重新校验；每目标独立结果 |
| `GET /capabilities` | 已开放能力和版本 | 不把未验证条目标为支持 |
| `GET /templates` | 内置模板及参数 schema | 只读，不返回可执行代码入口 |

即时转换默认不持久化正文。浏览器可以提交编辑后的 NodeDraft，服务端不信任客户端提供的“已经解析”标记。超过 15 分钟未活动的临时状态清理；分页或大结果缓存按字节上限管理。

## 12.3 业务与发布接口

| 方法与路径 | 作用 | 关键约束 |
| --- | --- | --- |
| `GET/POST /sources` | 来源列表与创建 | 新建远端来源先校验，不自动信任任意重定向 |
| `GET/PATCH/DELETE /sources/{id}` | 来源读取、修改、删除 | 写入带 expectedRevision；秘密默认遮罩 |
| `POST /sources/{id}/refresh` | 请求刷新 | 202 返回 runId；重复操作合并 |
| `GET /sources/{id}/nodes` | 读取当前快照节点 | 分页；来源节点只读 |
| `POST /sources/{id}/nodes/{ref}/copy` | 复制为本地节点 | 指定快照修订，避免复制过期身份 |
| `GET/POST /nodes` | 本地节点列表与创建 | payload 校验 |
| `GET/PATCH/DELETE /nodes/{id}` | 本地节点操作 | 秘密三态更新与修订控制 |
| `GET/POST /subscriptions` | 方案列表与创建 | 引用必须存在，不能创建隐式来源 |
| `GET/PATCH/DELETE /subscriptions/{id}` | 方案操作 | 保存与生成分开；改动使受影响产物失效 |
| `POST /subscriptions/{id}/preview` | 对当前设置预览 | 不产生私人链接，不发布产物 |
| `POST /subscriptions/{id}/publish` | 请求按目标生成 | 202；严格模式；CAS 提交 |
| `GET /subscriptions/{id}/artifacts` | 查看目标状态与诊断 | 不返回 token 明文 |
| `POST /subscriptions/{id}/tokens` | 创建单用途订阅令牌 | 再认证；只在创建响应显示秘密 |
| `GET /subscriptions/{id}/tokens` | 列出令牌元数据 | 无明文恢复或复制旧 token 功能 |
| `DELETE /tokens/{id}` | 撤销令牌 | 立即影响后续请求 |
| `GET /operations/{runId}` | 获取有限操作状态 | 重启中的操作可显示 interrupted |
| `GET /activity` | 脱敏事件列表 | 有保留和分页上限 |

操作记录不是保证永久重试的分布式任务系统。进程重启后由当前来源、方案与产物状态重算必要工作；客户端必须能够理解 interrupted，而不是永久等待 running。

## 12.4 请求示例

以下是计划接口样例，不代表项目代码已经存在。示例凭证与域名均为占位值，不可直接当作可用节点。

```json
{
  "inputFormat": "uri",
  "text": "vless://00000000-0000-4000-8000-000000000000@example.com:443?security=tls&type=tcp#Demo",
  "targets": ["uri", "base64", "mihomo-proxies"],
```

上述请求用于 parse 的输入部分和预览目标提示；正式 produce 提交 parse 返回后经编辑的 NodeDraft 集合。不得仅替换原始字符串中的名称后把它当成重新生成。

# 13 网页交互与信息架构

## 13.1 导航与页面

首版主导航控制为五项：转换工作台、节点、来源、订阅、设置。登录后默认进入转换工作台，不先展示复杂仪表盘。最近错误与重要告警在相关页面就地呈现。

| 页面 | 主要内容 | 核心操作 |
| --- | --- | --- |
| 转换工作台 | 输入区、节点列表/表单、输出与诊断 | 粘贴、上传、编辑、预览、复制、下载 |
| 节点 | 本地节点与能力状态 | 新建、修改、禁用、批量导出 |
| 来源 | 刷新状态、节点计数、当前错误 | 添加、刷新、检查节点、复制为本地 |
| 订阅 | 来源组合、目标设置、产物状态、令牌 | 预览、发布、生成地址、撤销 |
| 设置 | 账户、系统版本、限额、备份说明、许可证 | 密码维护、查看配置与源码入口 |

## 13.2 工作台布局

桌面端采用输入、节点编辑、输出预览的分区布局；移动端使用顺序标签页，不要求同时显示宽表格。输出目标与是否完整配置持续可见；每个目标显示输入数、主动过滤数、生成数和阻断数。

警告不能仅靠颜色表示，需要文字和图标；错误可定位到节点及字段。密码复制属于明确动作，页面不自动复制敏感数据。大型内容默认折叠，节点列表分页或虚拟化，避免一次渲染全部节点造成浏览器卡顿。

## 13.3 关键交互约束

“复制 URI”和“复制原文”是不同按钮。Base64 预览提供“查看解码内容”，便于验证它确实是 URI 列表。下载按钮只下载已经显示并通过检查的同一批次结果。

来源节点编辑按钮显示“复制后编辑”。订阅令牌创建后只显示一次完整地址，要求用户保存；此后列表只提供标识、范围、创建时间、到期和撤销操作。丢失明文时创建新令牌并撤销旧令牌，不虚构可从摘要恢复地址的功能。

生成配置不等于发布订阅，按钮与状态分开。修改已发布方案时提示旧产物将失效，直到新产物成功；涉及安全删除时不得为了减少一次确认而继续分发旧内容。

不加载第三方字体、分析脚本、外部图标 CDN 或公共二维码服务。二维码若后续加入，应在本地生成；首版复制链接已经足够。支持键盘操作、可见焦点、语义标签和窄屏显示。

# 14 公网安全设计

## 14.1 威胁模型

| 威胁 | 主要入口 | 首版防护 |
| --- | --- | --- |
| 匿名攻击管理接口 | 公网 API、登录 | 单管理员认证、限流、同源保护 |
| 来源导致内部网络访问 | 远端来源 URL、重定向、DNS | 集中抓取、地址绑定校验、出口约束 |
| 恶意订阅耗尽资源 | 大文本、深层 YAML、极端参数 | 字节/深度/节点上限、Worker 截止时间 |
| 节点凭证泄露 | 日志、URL、缓存、备份 | 脱敏、no-store、字段加密、秘密分离 |
| CSRF 与 XSS | Cookie、节点名、错误消息 | CSRF、Origin、内容转义、严格 CSP |
| 上游代码副作用 | 打包入口、依赖更新 | 固定快照、受控入口、无脚本能力、回归验证 |
| 旧节点继续传播 | 失效缓存、并发生成 | 依赖向量、事务失效、GET 再检查 |

管理员有权读取自己管理的节点秘密；主机 root、被控浏览器扩展和已经泄露的客户端配置不在应用能够完全防御的边界内。安全目标是缩小攻击面并避免错误默认值，不是宣称绝对安全。

## 14.2 初始化与恢复身份

首次管理员和主密钥只通过本地 CLI 初始化，不开放公网首次抢占注册页面。CLI 从受控文件或交互式输入读取密码，禁止把密码作为普通命令行参数写进 shell 历史。

密码使用 Argon2id。初始参数至少对齐 OWASP 建议的最低配置，并在目标机器上校准登录耗时；密码哈希参数随摘要保存，后续可在成功登录时升级。登录失败返回统一错误，针对 IP 与账号实施有限速率和逐步延迟，不用永久全局锁定给攻击者制造拒绝服务机会。[S15]

本地重置密码后吊销全部管理员会话；紧急重置命令提供同时撤销所有订阅令牌的显式选项。没有邮件找回、短信或远程忘记密码流程。

## 14.3 会话、同源与 CSRF

会话使用服务端保存的高熵随机标识；Cookie 默认 `__Host-submeld_session`，设置 Secure、HttpOnly、SameSite=Strict、Path=/，不设置 Domain。默认空闲过期 2 小时、绝对过期 24 小时。更新密码、退出和恢复数据时执行适当吊销。[S16]

写请求要求合法 Origin、JSON Content-Type 与同步 CSRF token。登录也必须校验 Origin；缺失或跨站 Origin 的浏览器管理写请求拒绝。CSRF token 只保存在页面内存，前端不把它或会话令牌放入 localStorage。SameSite 是辅助措施，不能替代 CSRF 验证。[S22]

可信 origin 使用显式 `SUBMELD_PUBLIC_ORIGIN`，不从任意 Host 或 X-Forwarded-* 推导。仅信任部署明确指定的反向代理地址；公网不能直接绕过代理访问应用监听口。开发模式只能显式绑定回环，不能通过“检测到 HTTP”自动放宽生产要求。

## 14.4 订阅令牌

令牌采用公共标识加 32 字节随机秘密，例如概念格式 `sm_<id>.<secret>`。数据库保存标识和秘密摘要；校验使用恒定时间比较，范围限定到一个方案和允许格式。默认无到期时间以兼容个人长期订阅，但提供到期设置，并在 UI 清楚显示长期授权风险。

路径包含秘密是为了兼容不能设置自定义认证头的订阅客户端，不应被称为最佳通用 API 认证。必须关闭该路径的完整访问日志、分析和共享缓存；页面设置 Referrer-Policy: no-referrer，复制地址不经过第三方短链服务。

## 14.5 解析、前端与日志防护

YAML 限制别名展开、嵌套深度和节点数，拒绝自定义执行标签；JSON 拒绝重复关键字段；对象映射防止原型污染；源配置中的路径、代理链引用和执行指令不进入输出。模板只写入已声明字段。

前端一律按文本展示节点名和诊断，不用不受控 HTML；CSP 默认禁止第三方脚本、unsafe-eval 和嵌入第三方页面。临时预览和下载接口均 no-store，不在错误上报中携带正文。

日志采用字段 allowlist：requestId、路由模板、对象 ID、阶段、稳定错误码、耗时和计数。禁止正文、完整 URI、URL 查询、Authorization、Cookie、token、密码、私钥和完整证书。上游原始日志只能进入专门的截断脱敏通道，默认不落盘。

# 15 部署、运行与维护

## 15.1 生产部署

推荐一个多阶段构建镜像，包含编译后的前端、服务端和受控转换模块。以非 root 用户运行，根文件系统只读，只有数据目录可写，临时目录使用有容量上限的 tmpfs，主密钥只读挂载；设置 no-new-privileges、资源限制和最小 capability。

应用默认在容器内监听 3000，由现有 HTTPS 反向代理转发；宿主机发布时仅绑定回环。反向代理不缓存 `/api` 与 `/s`，不记录订阅秘密路径；请求体、连接和响应超时与应用限额一致。多副本部署和共享网络盘不在 v1 支持范围。

## 15.2 配置项

| 配置 | 含义 | 默认或要求 |
| --- | --- | --- |
| `SUBMELD_PUBLIC_ORIGIN` | 管理网页的唯一可信 origin | 生产必须为 HTTPS |
| `SUBMELD_LISTEN` | 应用监听地址 | 容器内显式配置；宿主端口回环 |
| `SUBMELD_DATA_DIR` | SQLite 与应用数据 | 可写持久卷 |
| `SUBMELD_MASTER_KEY_FILE` | 主密钥文件 | 必填；只读秘密挂载 |
| `SUBMELD_TRUSTED_PROXIES` | 允许信任的反向代理 | 默认空，不信任任意转发头 |
| `SUBMELD_FETCH_ALLOWED_PORTS` | 来源可用 HTTPS 端口 | 默认 443 |
| `SUBMELD_LOG_LEVEL` | 日志等级 | 默认 info，仍不得输出秘密 |
| `SUBMELD_DEV_MODE` | 本地开发例外 | 默认 false；仅回环允许 |

管理员不应通过网页修改主密钥路径、监听地址或代理信任列表，避免管理功能变成任意主机配置入口。限额可以从受版本控制的部署配置读取，但必须有硬性上限。

## 15.3 计划 CLI

命令契约包括 `submeld init`、`submeld serve`、`submeld migrate`、`submeld admin reset-password`、`submeld backup`、`submeld restore` 和 `submeld doctor`。这些是待实现命令，不是当前可下载执行的软件。

`doctor` 检查配置、密钥可读性、数据库一致性、锁版本、来源出口配置和构建信息，不读取或输出节点正文，不进行任意连通性探测。健康检查 `/healthz` 只表示进程存活；`/readyz` 表示数据库、密钥和转换模块已就绪，不依赖外部来源是否在线。

## 15.4 升级与退出

升级前制作一致备份；启动时检查 schema 与锁文件；迁移失败保持未就绪，不继续提供部分可写服务。禁止多个实例同时迁移。应用回滚需要确认 schema 向后兼容，否则使用配套备份恢复，不尝试自动撤销未知迁移。

SIGTERM 后停止接收新的生成和刷新工作，完成有界的短事务，取消未完成抓取与转换，记录 interrupted 并关闭数据库。截止时间后退出，不无限等待来源服务器。重启不恢复已经撤销的令牌，也不把中断中的产物自动标为 ready。

# 16 容量、性能与资源预算

下表全部是首版设计预算，必须通过基准和压力测试确认。参考测试环境为 Linux、2 vCPU、1 GiB RAM；应用容器初始内存上限建议 768 MiB。不是对任意机器、任意输入或任意上游版本的性能承诺。

| 项目 | 默认预算 |
| --- | --- |
| 来源数量 / 本地节点数量 / 订阅方案数量 | 50 / 2,000 / 20 |
| 单批次解析或单方案输出节点数 | 最多 2,000 |
| 本地逻辑输入 / 远端传输 / 解压后正文 | 4 MiB / 2 MiB / 4 MiB |
| 单节点文本长度 / 结构嵌套深度 | 32 KiB / 32 层 |
| 单目标最终产物大小 | 4 MiB，包括 Base64 包装后的大小 |
| 转换 Worker / 来源抓取并发 | 1 / 2 |
| 转换队列 | 最多 8 项，排队输入合计最多 16 MiB |
| 单批次转换执行 / 队列等待 | 最多 5 秒 / 10 秒 |
| 来源 DNS、连接 / 单次请求总截止 | 分别有界；单次总截止 15 秒 |
| 即时转换临时状态 | 15 分钟闲置到期，总字节受限 |
| 远端陈旧结果允许期限 | 距来源最近有效成功最多 24 小时 |
| 数据库告警 / 配额阻止新内容 | 512 MiB / 1 GiB；备份另算 |
| 活跃产物内容合计 | 最多 256 MiB，超限不覆盖现有成功产物 |
| 事件日志保留 | 最多 30 天或 10,000 条，先到者生效 |

性能目标：正常 1,000 节点输入、不含外部网络耗时的常用目标转换 p95 不超过 2 秒；有效订阅内容读取在 20 并发的本地基准下 p95 不超过 150 毫秒；无工作时总 RSS 目标不超过 150 MiB。测量必须包括 Worker、解密和序列化开销，不能只报告空路由耗时。

超限采用快速失败和可见提示，不自动无限扩容。资源压力下优先保持已发布内容的有权读取，限制新的转换、刷新和预览。Worker 的堆限制不等于 RSS 限制，仍由容器和进程指标兜底。

# 17 测试、验收与发布门槛

## 17.1 四层验证

**结构与单元验证。** 输入识别、URI 编解码、字段校验、诊断、标签、去重、模板组合和加密存储均有独立测试。

**服务集成验证。** 使用临时 SQLite、可控来源服务器和模拟 DNS/TLS 测试抓取、状态变化、修订冲突、令牌和重启恢复；测试配置不得成为生产可用的 SSRF 绕过开关。

**真实内核配置验证。** CI 下载并校验固定摘要的三个内核，以固定参数对脱敏生成配置执行对应版本的离线检查；检查程序不在生产服务中运行。禁网、只读夹具、资源限制和固定命令参数是测试执行边界。

**客户端导入验证。** 每种承诺的 URI 方言和完整配置至少记录一个实际消费客户端的版本、导入结果及关键参数。内核语法检查不能代替客户端分享链接解析，也不能证明实际服务端连通。

## 17.2 核心验收用例

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| TC-01 | 导入后修改名称、密码、SNI 或 path | URI 从新节点生成，独立预期字段一致 |
| TC-02 | 同批次 URI 与 Base64 | 解码字节完全等于 URI 正文 |
| TC-03 | 不同顺序导出八个目标 | 保存节点不被修改，各目标结果稳定 |
| TC-04 | 混合支持与不支持节点 | 数量有解释，严格导出被阻断 |
| TC-05 | 未知关键参数、重复 JSON 键、冲突 query | 不静默取值或丢弃；诊断定位正确 |
| TC-06 | IPv6、中文名称、转义密码和百分号 path | 不双重编码/解码，不改变连接语义 |
| TC-07 | YAML short ID 数字推断、别名炸弹、深层对象 | 类型受控；危险结构拒绝且服务仍响应 |
| TC-08 | HTML 错误页和 Base64 包装乱码 | 不产生伪节点或空成功订阅 |
| TC-09 | 来源只含 provider 或非节点配置 | 明确未支持路径，不递归抓取 |
| TC-10 | 缺失 REALITY 公钥或错误传输组合 | 不降级成 TLS/直连，不发布 |
| TC-11 | 同地址不同密码/传输节点 | 不被错误去重 |
| TC-12 | 默认节点在刷新后消失 | 完整目标阻断，不自动选择第一项 |
| TC-13 | 来源临时 5xx 与网络超时 | 仅在原向量和允许期限内读陈旧结果 |
| TC-14 | 来源 401、证书失败或异常空响应 | 不以陈旧读取绕过阻断 |
| TC-15 | 接受新快照但某目标生成失败 | 该目标不回退旧快照；其他目标独立 |
| TC-16 | 生成期间编辑或禁用节点 | 旧任务 CAS 失败，旧节点不重新发布 |
| TC-17 | 撤销令牌后带旧请求条件再次获取 | 后续请求拒绝；无缓存授权绕过 |
| TC-18 | 直接 GET/HEAD 私人订阅 | 不调用抓取器和转换器；无 HTML 回退 |
| TC-19 | 内网、metadata、IPv6、重定向和 DNS 变化 | 来源请求被阻断，无凭证跨域转发 |
| TC-20 | 跨站登录/写入、伪造转发头 | 同源和代理信任检查生效 |
| TC-21 | 转换执行超时、排队超限 | Worker 真正停止，内存和队列有界 |
| TC-22 | 进程重启时存在 running 操作 | 标记中断并按当前状态恢复，不伪报成功 |
| TC-23 | 数据库、WAL、日志与浏览器存储扫描 | 不出现测试用秘密明文或完整 token |
| TC-24 | 一致备份与新目录恢复 | 数据可解密，引用有效，吊销策略正确 |
| TC-25 | 上游模块导入与正常转换 | 无意外联网、缓存文件和全局副作用 |
| TC-26 | 锁定内核检查与客户端导入 | 按版本留证，不外推未测试组合 |

## 17.3 发布硬门槛

所有 INV 不变量与 P0 安全测试通过；协议矩阵中已开放组合有夹具和预期字段；依赖锁、许可证和源码入口完整；生产镜像不含代理内核、真实秘密或开发绕过；备份恢复实际执行成功；文档默认值与代码一致。

遇到会导致静默丢节点、TLS 弱化、SSRF、秘密落盘、令牌撤销无效或旧产物复活的问题，阻断发布。对尚未通过客户端测试的能力，应从默认可选项隐藏或明确标为实验性并禁止自动发布，不能用总体“支持”标签覆盖。

# 19 决策记录、风险与维护纪律

## 19.1 需要保留的决策记录

ADR-001：单应用而非多服务；ADR-002：受控复用 Sub-Store 而非运行完整后台；ADR-003：严格转换与显式排除；ADR-004：来源只读、复制后编辑；ADR-005：预生成订阅与依赖失效；ADR-006：模板与节点转换分离；ADR-007：单管理员和独立只读令牌；ADR-008：生产不运行内核；ADR-009：字段加密与本地恢复；ADR-010：首版能力范围和版本锁。

这些记录应解释选择、被放弃方案及改变条件，不需要为每个小函数建立决策文件。任何会引入新常驻服务、任意脚本、公共匿名入口或通用编排模型的需求，都必须先更新范围决策。

## 19.2 主要风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 上游入口依赖过重 | 自有补丁持续增长 | M0 先证明边界；监测补丁预算 |
| 上游兼容行为静默丢字段 | 用户得到不可用或弱化配置 | 结构化诊断、独立期望值、目标预检 |
| URI 方言差异 | 客户端导入后行为不一致 | 明确方言与客户端版本，不泛化支持 |
| sing-box 等配置版本演进 | 模板与输出失效 | 锁版本，按目标升级，旧产物有效性检查 |
| 过度追求所有协议 | 项目重新膨胀 | 只开放测试覆盖的组合，P1 独立排期 |
| 来源异常与失效缓存 | 撤销节点继续分发 | 来源状态分级、依赖向量和 GET 守卫 |
| SQLite/备份运维错误 | 丢失或无法恢复秘密 | 本地存储、一致备份、恢复演练、密钥分开 |
| 公网暴露 | SSRF、凭证泄露与拒绝服务 | 无匿名转换、集中抓取、限制与日志脱敏 |

## 19.3 维护规则

禁止在生产运行时自动拉取最新转换器、模板或内核。每次上游或模板升级都应产生能力差异报告；涉及连接语义变化，必须由测试和人工评审共同确认。

安全修复优先于新增协议。出现字段丢失、凭证泄露或无法说明的节点数量变化时，先禁用受影响能力，而不是增加“忽略错误”选项。简单实现优先，但不得以自用为理由省略认证、失效检查和安全抓取。

# 20 授权、证据与项目启动条件

## 20.1 授权方案

Sub-Store 的所查快照采用 AGPL-3.0，其网络交互条款要求对修改后支持网络交互的版本向相应远端用户提供获取对应源码的机会。项目选择将自有代码按 AGPL-3.0 路线组织，保留上游版权、许可证、修改记录和构建说明。[S06]

项目提供与运行版本对应的源码入口及构建标识，覆盖 vendor、补丁、锁文件和必要构建材料；源码公开不包括用户订阅、节点凭证、数据库或主密钥。第三方依赖各自的许可证仍需保留，不能因为外层项目授权就替换其授权。

# 附录 A 关键数据契约示例

## A.1 NodeDraft 与节点导入文档

`submeld-node-v1` 是本项目自有的节点交换格式，和 Xray/sing-box 原生 JSON 不同。首版只接收如下受 schema 校验的封装；不接收任意上游内部对象作为稳定公共协议。

```json
{
  "format": "submeld-node-v1",
  "nodes": [{
    "protocol": "vless",
    "name": "Demo",
    "server": "example.com",
    "port": 443,
    "auth": {"uuid": "00000000-0000-4000-8000-000000000000"},
    "tls": {"enabled": true, "serverName": "example.com", "insecure": false},
    "transport": {"type": "tcp"},
    "protocolOptions": {}
  }]
}
```

NodeDraft 的 auth 与 protocolOptions 是按 protocol 区分的联合类型，不是任意键值字典。SS 要求 method/password；VMess 要求 uuid 和已支持安全参数；VLESS 要求 uuid、可选受支持 flow；Trojan/Hysteria2 要求各自密码字段；TUIC 使用版本明确的 uuid/password。TLS/REALITY 和传输配置分别提供严格 schema，未知写字段拒绝。

即使示例 UUID 格式有效，也不表示服务端存在该用户。示例用于契约说明，不是可连接配置。

## A.2 上游锁与产物元数据

上游锁至少记录 repository、commit、sourceDigest、patchSetDigest、buildToolVersions 和 license；兼容锁至少记录每目标的 profileVersion、coreVersion、binaryDigest、architecture、clientEvidence 与测试结果位置。没有对应字段的能力不能标记为发布就绪。

产物元数据示例字段如下：

```text
subscriptionId, target, subscriptionRevision,
sourceDependencies[{id, configRevision, contentRevision}],
localNodeDependencies[{id, revision}],
engineRevision, templateId, templateVersion,
targetSettingsDigest, generatedAt, nodeCount,
contentDigest, contentType, encryptedBody, state
```

源站最近成功时间用于读取时计算陈旧期限，不仅依赖生成时保存的一个过期时间。后台重新生成不能抹掉来源长时间未刷新这一事实。
