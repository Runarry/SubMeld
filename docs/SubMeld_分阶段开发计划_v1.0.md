# 01 交付策略与版本路线

## 1.1 四个版本，逐次增加实际用途

| 阶段／拟发布版本 | 用户拿到后能做什么 | 本阶段结束即可使用的场景 |
| --- | --- | --- |
| P1／v0.1.0 | 粘贴或上传 URI、Base64、内联节点 YAML，修改参数，重新导出 URI／Base64 | 临时转节点、改名称或 SNI、把 YAML 节点转成可导入链接 |
| P2／v0.2.0 | 保存本地节点，重新打开编辑；导出三内核基础完整配置或节点片段 | 维护自己的节点库，为实际客户端生成文件 |
| P3／v0.3.0 | 组合本地节点和粘贴来源，生成可撤销的私人订阅地址 | 手机、电脑直接订阅同一方案，网页改完后客户端更新 |
| P4／v1.0.0 | 添加远端 HTTPS 来源，手动或每 6 小时刷新，自动更新各格式订阅 | 日常只维护来源和节点，不再手工重新转换与上传 |

这些版本号是计划标签，不是现有发布记录。四阶段按 P1 → P2 → P3 → P4 顺序实施；下一阶段必须保留此前已经交付的使用路径。

## 1.2 重排顺序，不增加功能范围

本计划重新安排 [D1 §11.3] 的八项工作：转换接入并入 P1，原生输出并入 P2，正确失效并入 P3／P4，安全和实际使用验收贯穿每次交付。不再设一个只有 SDK 验证的 M0，也不把安全、测试和可运行部署全部留到末尾。

本文只决定“先交付什么、以什么证明可用”，不恢复设计 v1.0 已删除的需求，不取代 [D1] 的产品行为或 [D2] 的安全边界。某能力在早期版本尚未交付，应在界面和服务端明确关闭；不能展示可点击的空页面、假成功按钮或返回占位配置。

## 1.3 每个版本采用同一个应用形态

始终采用 Vue + TypeScript、Node.js + Hono、SQLite、一个转换 Worker、一个应用容器。首次版本就提供本地初始化、登录、统一构建及单容器启动；默认按现有 HTTPS 反向代理部署，显式回环 HTTP 仅用于开发。[D1 §4、§9、§10]

SQLite 从 P1 起仅保存实际需要的设置；其他表随功能引入。后续版本沿用同一个数据目录，以顺序迁移升级，不要求删库或重新搭一套服务。P1 的临时工作台内容不持久化，P2 才提供明确的“保存节点”动作。

# 02 P1 · 实用的 URI／Base64 转换工作台

**版本：** v0.1.0　**前置：** 无　**独立价值：** 不用保存或配置来源，也能完成真实节点转换。

## 2.1 用户可以直接完成的操作

登录后，粘贴或上传 URI、Base64 URI 订阅、含内联节点的 Clash／Mihomo YAML；查看节点，修改名称、地址、凭证、SNI 及已开放的传输参数；预览、复制、下载重新生成的 URI 和 Base64。也可以从空白协议表单创建节点。

六类基础协议 SS、VMess、VLESS、Trojan、Hysteria2、TUIC 均有至少一组基础正反例；TLS、基础 REALITY 和常用传输按公开的关键样例开放，不承诺所有组合。上传由浏览器读为文本，与粘贴和表单共用 NodeDraft 路径。识别到 URL 或 provider 不联网，给出入口尚不支持的提示。[D1 §3、§5]

## 2.2 阶段内的开发顺序

**先让真实转换进入应用。** 固定 Sub-Store 提交和依赖锁，建立薄 parse／render 适配，在 Worker 中完成 YAML／URI／Base64 → NodeDraft → URI。只解决确实阻止嵌入的运行时问题，不重建纯 SDK。

**再完成可操作的网页。** 提供输入区、节点编辑、URI／Base64 两个目标、诊断、显式排除失败节点和复制下载。URI 只生成一次；Base64 编码其 UTF-8 字节。编辑后旧预览失效，各目标不修改原节点。

**同步交付运行与底线。** settings 存管理员密码哈希；本地初始化／重置、内存会话、同源 JSON 防护、日志收口、文本渲染和输入限制到位。Worker 繁忙明确报错，超时真正终止重建。提供实际可执行的检查脚本、镜像、启动说明和上游许可证材料。

## 2.3 现场演示与退出条件

| 演示步骤 | 必须观察到的结果 |
| --- | --- |
| 初始化并登录；粘贴包含中文名、IPv6 或 REALITY 参数的脱敏样例 | 网页识别节点、展示参数和必要警告，不要求先创建来源／方案 |
| 修改名称、SNI、path 或密码，再生成 | URI 反映修改，不是回传原文；复制与下载和预览相同 |
| 将 YAML 内联节点转为 URI，再查看 Base64 的解码结果 | 真正完成节点格式转换；同批 URI 与解码字节完全一致 |
| 混入缺字段节点，再手动排除该项 | 先准确报错；仅在用户明确排除后输出，不悄悄减少节点 |
| 发起未登录、错误 Origin、超大输入和超时用例 | 按边界拒绝；转换 Worker 重建后仍能处理正常请求；日志无测试秘密 |

**退出要求：** T01～T05 的本阶段相关部分、T11 的 Worker／日志部分，以及 T12 的实际部署和 URI／Base64 客户端导入完成。至少用实际使用的一种客户端导入本阶段输出；未测项不能写成兼容通过。

**尚不交付：** 本地节点库、三内核 JSON／YAML 输出、订阅地址、来源联网和定时刷新。接入验证只是本阶段内部步骤，不能以“测试脚本能运行”宣布 P1 完成。

# 03 P2 · 可保存节点的三内核配置工具

**版本：** v0.2.0　**前置：** P1 已验收　**独立价值：** 节点不必反复粘贴，可长期维护并生成客户端配置文件。

## 3.1 用户可以直接完成的操作

从工作台保存选中节点；在本地节点页创建、编辑、禁用、删除、重新载入工作台。关闭页面或重启应用后，本地节点仍存在；临时输入仍不自动保存。

输出增加 Mihomo、sing-box、Xray 三个目标，每个目标有“基础完整配置／仅节点”选项。各自只有一个随代码发布的固定模板，默认回环监听、使用当前排序第一项；没有有效代理则失败，不回退 DIRECT-only。Xray 自有输出器首版仅覆盖 SS／VMess／VLESS／Trojan，不因上游有其他代码扩大范围。[D1 §3.2、§3.3]

## 3.2 阶段内的开发顺序

**保存先闭环。** 增加 nodes 表和必要迁移，NodeDraft 运行时校验、列表遮罩、授权编辑、明确清空秘密、revision 冲突 409 一起实现。未编辑的秘密字段不提交，遮罩内容不能成为新密码。先做“保存 → 重启 → 再编辑 → 导出”。

**逐个交付目标输出。** 接通 Mihomo 和 sing-box 节点输出及固定模板；再补限定范围的 Xray outbound 映射与固定模板。每个目标使用独立副本，节点片段与完整配置共用转换结果。对象序列化，不提供远端模板、任意深合并或规则编辑器。

**把目标检查加入现有测试。** 在测试环境用锁定内核检查基础配置，断言关键字段及节点数量；内核不进入生产运行路径。给每个公开目标准备实际导入步骤和已测范围说明。

## 3.3 现场演示与退出条件

| 演示步骤 | 必须观察到的结果 |
| --- | --- |
| 保存两个节点，重启后重新登录并打开节点库 | 节点与参数完整保留，旧会话已失效，不需重新初始化或删库 |
| 修改节点后分别导出三目标与仅节点格式 | 三种完整配置可通过目标检查；文件与预览一致，模型未被导出器污染 |
| 用两个页面编辑同一节点 | 迟提交的旧 revision 返回 409，不能无提示覆盖新修改 |
| 把 Hysteria2／TUIC 节点选入 Xray 导出 | 明确说明本项目该目标尚不支持；不悄悄丢节点，其他可用目标不受牵连 |
| 停机复制数据目录并在受控环境恢复 | 节点库与设置可恢复；运行中不直接复制主数据库冒充一致备份 |

**退出要求：** P1 路径全部可用；T01～T04 扩展到三目标，T08 覆盖节点保存冲突，T11 覆盖持久数据与停机恢复，T12 覆盖三目标配置检查及实际使用客户端。没有实际导入某目标时，明确标记未验证，不以 JSON／YAML 能解析代替导入结果。

**尚不交付：** 可被客户端定时读取的订阅地址、远程来源、自动抓取。节点库重启可用和配置文件可导入，是本阶段成果，不把“表建好了、接口通了”作为完成条件。

# 04 P3 · 能被客户端使用的私人订阅

**版本：** v0.3.0　**前置：** P2 已验收　**独立价值：** 即使没有远端来源，也能给自己的手机和电脑提供稳定订阅地址。

## 4.1 用户可以直接完成的操作

保存粘贴文本为本地 Source，查看只读来源节点、复制为本地节点；把本地节点和文本来源按顺序组合成 Subscription，使用名称包含／排除、协议筛选、固定前后缀等已有范围内的设置。

选定输出格式并保存后，应用自动生成结果，显示一次新建的私人地址；客户端通过 `/s/<token>/<format>` 订阅。每方案只有一个令牌，可重置或停用；明文丢失就重置，不为反复复制而额外保存令牌原文。[D1 §6、§8]

## 4.2 阶段内的开发顺序

**先打通本地发布闭环。** 引入 sources（本阶段仅文本）、subscriptions、subscription_inputs、artifacts 的必要字段与真实外键。提供来源页、方案编辑、状态与地址展示。来源节点只读，复制出的本地节点独立存在；不做覆盖合并或跨刷新身份。

**再落实正确失效。** 保存、编辑、禁用、删除走统一事务：递增受影响方案 revision 并清除旧产物。生成前读当前输入，事务外执行，成功和失败写回前均核对启用状态与 revision。URI／Base64 同批同事务提交；其他格式独立替换。不先发布错误缓存，再留给后续阶段修复。

**同时完成只读分发。** GET／HEAD 只校验令牌、启用格式、engine_version 和产物，不抓取、不转换、不要求管理员 Cookie。无效令牌 404；有效但无结果 503；不回退前端 HTML。使用 no-store，代理不缓存或记录完整令牌路径。重启重建缺失或旧引擎产物；令牌不因正常重启变化。

## 4.3 现场演示与退出条件

| 演示步骤 | 必须观察到的结果 |
| --- | --- |
| 建立“文本来源＋本地节点”方案并在实际客户端导入地址 | 客户端不需登录管理页；取得与网页目标一致的内容 |
| 网页修改密码、顺序、筛选或停用节点，再让客户端更新 | 旧产物立即失效；生成后读到新内容。客户端已下载内容不承诺远程撤回 |
| 暂停旧生成，先提交人工修改，再让旧生成完成 | 旧内容及旧错误均不能写回；只接受当前 revision 的结果 |
| 重置令牌；分别请求旧地址、新地址、HEAD 和无效路径 | 旧地址立即 404；新地址可读；HEAD 同权无正文；未知路径不是 HTML |
| 重启、改变引擎构建标识、进行一次受控备份恢复 | 会话失效而数据保留；旧引擎产物不可读并安排重建；恢复后按说明重置令牌 |

**退出要求：** T05、T08、T10 完成相关边界；T09 覆盖成对发布、重建失败不覆盖有效结果；T11 覆盖令牌恢复提醒，T12 覆盖真实地址导入和至少一次客户端更新。订阅读取不得触发计算，可用请求计数或测试替身证明。

**尚不交付：** 远端 HTTPS 来源、自动轮询来源。只开放文本来源，不预留可绕过验证的联网入口；不增加 operations API、持久任务、设备授权或审批流程。

# 05 P4 · 自动更新的远程订阅聚合工具

**版本：** v1.0.0　**前置：** P3 已验收　**独立价值：** 加入远端来源后，日常订阅更新不再依赖人工重新转换。

## 5.1 用户可以直接完成的操作

添加公网 HTTPS 订阅 URL 与允许的请求头，保存后进行一次受控抓取；成功接受后可加入现有方案。支持手动单来源刷新，默认全局每 6 小时顺序刷新；来源接受新内容后自动重建相关方案。

来源页显示真实成功时间、节点数和脱敏错误；方案页分别显示各格式的生成时间、更新情况与可读状态。抓取失败或某目标生成失败时，保留该目标最近成功结果，不设置默认陈旧停发期限。[D1 §7、§8]

## 5.2 阶段内的开发顺序

**安全抓取与入口一起交付。** 一个 SourceFetcher 完成标准 URL 解析、HTTPS 证书检查、A／AAAA 及实际连接地址校验和绑定。拒绝非公网目的地，不跟随 3xx，不递归抓取正文 URL；限制允许请求头、压缩前后字节和总时间。没有完整安全路径时保持远端入口不可用，不临时放行普通 fetch。

**先验证单来源更新，再接定时器。** 完整解析成功且至少有一个节点才接受新快照。失败不覆盖旧快照；保存新快照并递增相关方案 revision。抓取提交前核对 source revision 和启用状态，旧请求不能写回被改地址或已删除来源。仅扩展现有 Source，不增加候选历史和审批状态。

**最后加入自动维护。** 每 6 小时顺序刷新，同来源不并发；方案更新按 ID 合并到有界 Set，沿用唯一 Worker。重启不补跑错过的所有周期，不做无限重试。用受控时钟验证定时逻辑，不要求人为等待六小时才跑测试。

## 5.3 现场演示与退出条件

| 演示步骤 | 必须观察到的结果 |
| --- | --- |
| 添加一个受控公网 HTTPS 来源、加入现有方案并导入客户端 | 来源抓取、解析、合并、各目标发布、客户端读取形成闭环 |
| 来源新增节点；手动刷新并推进一次测试时钟 | 手动与定时两条路径均能更新，相关方案自动重建；读取请求不触发刷新 |
| 模拟 5xx、401／403、证书失败、空内容、HTML 或不完整解析 | 新内容不接受，旧成功结果继续可读；页面不把旧内容时间伪装成最新 |
| 改来源地址／凭证或禁用来源，再释放旧请求与旧生成 | 旧快照和产物按人工修改规则失效，迟到结果不能复活它们 |
| 自动刷新有效新内容但某目标转换失败 | 其他目标可更新，失败目标保留旧成功结果；URI／Base64 始终成对 |

**退出要求：** T06、T07、T08、T09 覆盖远端路径；所有 T01～T12 的首版适用内容回归。实际部署架构、已用客户端、一个受控真实 HTTPS 来源均有记录；只做模拟抓取不能宣称真实远端链路已经验证。

**仍不交付：** 任意重定向、HTTP／私网来源例外、每来源 cron、公共转换、测速、内核运行、多人权限和复杂编排。安全抓取阻塞时保留已验收的 P3 可用版，但不得把 P4 标成已完成。

# 06 安全底线随功能交付

## 6.1 安全不是最后一阶段的补课

| 能力首次开放时点 | 同批必须到位 | 不因此新增的系统 |
| --- | --- | --- |
| P1：登录、转换、上传文本 | 密码哈希、内存会话、同源写入防护、输入限额、Worker 超时、日志脱敏、文本渲染与数据权限 | MFA、SSO、CSRF 秘密轮换、脚本沙箱 |
| P2：持久节点与配置文件 | 参数化 SQL、revision 冲突、遮罩字段不写回、回环默认、停机备份与恢复说明 | 字段加密、KMS、风险审批、在线恢复 |
| P3：公网私人订阅 | 随机令牌摘要、立即撤销、GET／HEAD 只读、正确缓存失效、代理 no-store／日志配置 | 多设备授权、格式 ACL、持久任务、发布依赖向量 |
| P4：服务器联网抓取 | 目的地校验与连接绑定、HTTPS 校验、禁止 3xx、时间和字节限制、防迟到响应 | 私网例外平台、域名审批、网络命名空间与应用内防火墙 |

表中控制均来自现有设计和规范，[D1 §7～§11][D2 §7～§9]；本计划不提升安全等级。未到阶段的能力不开放，也不提前建设一套管理它的系统。已开放能力的必要防护不得延后。

## 6.2 三种“更新”不能混为一谈

**修改配置：** 编辑连接参数、URL、凭证、格式、顺序、筛选或启用状态，属于人工内容变更。同一事务递增相关 revision 并清除旧产物；改 URL／凭证／格式还清旧来源快照。重建失败不能恢复这些已清除内容。

**点击“刷新来源”：** 只是要求重新获取，未改变来源配置。与定时刷新采用同一接受规则；失败保留旧快照和旧成功产物。不能因为按钮是人点的，就误当成“人工编辑”先删除有效订阅。

**点击“更新订阅”：** 重新生成当前保存的输入，不隐式拉取所有远端来源，不修改设置。若旧结果本来允许读取，则生成失败不覆盖它；读取仍须满足令牌、启用格式与引擎版本要求。

GET 不强制 built_revision 等于当前 revision；自动更新期间允许读旧结果，人工变更通过删除产物阻断旧内容。尚无成功快照的启用来源不能被静默当成空来源发布，避免无解释少节点。[D1 §8][D2 §6]

## 6.3 延续已经接受的边界

首版明文数据库、24 小时内存会话、一个方案一个令牌、来源失败保留旧结果、排序第一节点作默认、一个 Worker，均保持不变。数据库副本泄露和历史备份恢复令牌授权的风险在说明中保留，不另做安全整改任务。[D2 §2、§3]

发现未登录访问、跨站写入、私网抓取、秘密日志或撤销失效等实际缺口，直接修复并回归。发现多人分发、数据库单独保密等新场景，说明事实与最小方案后再确认范围；不以“安全加固”“默认关闭”预埋被排除的功能。

## 8.2 每阶段的实施粒度

先打通该阶段最小的真实路径，再扩展到本阶段完整承诺。例如 P1 可先用一条 VLESS 样例跑通网页登录到导出，然后补齐六协议、YAML 输入与错误用例。这个中间提交有助于尽早试用，但不能据此把完整 P1 验收打勾。

一次变更围绕一个用户动作及其必要依赖组织，例如“保存节点并重新载入”“方案地址可读且可撤销”。不拆成只有数据库、只有 API、只有前端的独立交付里程碑；阶段内部仍可有小提交和相关单测。

可以在同阶段并行实现互不冲突的节点表单、目标映射或测试，但共享 NodeDraft、错误结构和接口约定。后阶段的重功能不提前并行塞入，不能为了给未来工作预留位置新增服务或抽象框架。

## 8.3 真正的阻塞如何处理

| 阻塞点 | 允许的处理 | 不能用的绕过 |
| --- | --- | --- |
